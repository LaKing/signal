# ADR 0025: Project files

- **Status:** Accepted (owner's request of 2026-10-16, M2.8-12: "Save, Save As and Open a project as one compressed .signal file", with `zip` 8.6.0 locked by the operator; the Dock Quit and logout prompt per operator decision operator-request:009 of 2026-10-15). Builds on ADR 0009 and 0013; changes neither.
- **Date:** 2026-10-16

## Context
A project is a folder of text files (ADR 0009), and the GUI and tools only edit those files (ADR 0013). A folder is awkward to hand to someone, to keep beside other documents, or to double-click. People expect a document: one file that Open, Save and Save As work on, and that says when it has unsaved changes.

## Decision
1. **A `.signal` file is a zip of the project folder** (`docs/project-format.md` §10): the files a project reads (`project.toml`, `composites/*.toml`, everything under `ui/`), `project.toml` at the root. It is only a container. Its text files are the project, and nothing in the archive means anything of its own, so text stays the source of truth (ADR 0009, 0013). Hidden files, `renders/`, `sessions/` and everything else a project never reads are left out.
2. **Deterministic.** Entries are deflated, in sorted path order, with a fixed time (1980-01-01) and mode (`0644`), so the same folder always gives the same bytes.
3. **Reading is defensive.** Every entry is checked before anything is written: relative paths only (no `..`, no absolute path), regular files and folders only (no symbolic link, no device file), no name twice in any case, at most 10 000 entries and 1 GiB unpacked (the bytes actually written are counted), and `project.toml` at the root. A refused archive writes nothing, opens nothing, and the refusal names the reason.
4. **`signal-project` owns the format** (`signal_project::archive`: `pack(folder) -> bytes`, `unpack(bytes, into)`). The CLI packs and unpacks (`signal pack`, `signal unpack`), and `render`, `play` and `ui` run a `.signal` file from a temporary folder, removed after the run.
5. **Signal.app edits a working folder.** Opening a `.signal` file unpacks it into a folder of its own under `~/Library/Application Support/Signal/Open/`. Live edits, live reload and the panel work there unchanged. The Setup records the `.signal` file as the last project. The project is **edited** while that folder packs to other bytes than the file held when opened or last saved: the toolbar and the window title ("— Edited") say so. The display looks at the folder's files every 250 ms and compares content when they change and at least every 2 s (stretched to twenty times a comparison's duration for a large project, so the poll stays under about 5 % of the control thread); a prompt, Open or close compares at once. Save packs it and writes it over the file atomically (a temporary file, then a rename). Save As writes a new file, which the project is from then on, and a folder project's folder is left as it is. Closing the project removes the working folder.
6. **Edits are never lost silently.** While a `.signal` project is edited, the close button, File ▸ Quit, ⌘Q and opening another project ask "Save changes to <name>?" with Save, Don't Save and Cancel (an `NSAlert` through `objc2-app-kit`'s safe API; in a browser, a dialog in the page).
7. **Dock Quit and logout cannot be cancelled** (operator decision operator-request:009). They reach the app as `-[NSApplication terminate:]`, and only the app delegate's `applicationShouldTerminate:` can cancel that. The locked tao 0.37.1 registers no such method on its delegate (`tao-0.37.1/src/platform_impl/macos/app_delegate.rs:46-88`). Its `applicationWillTerminate:` (line 130) only emits `Event::LoopDestroyed` (`app_state.rs:272-281`) once termination is decided. Answering the request ourselves needs `pub unsafe trait NSApplicationDelegate` (`objc2-app-kit` 0.3.2, `NSApplication.rs:1105`), which the no-unsafe rule (AGENTS.md rule 9) forbids. Replacing tao's delegate would also lose its Finder opens. So on those routes the prompt, run at `LoopDestroyed`, offers Save and Don't Save only. Without an answer the working folder is kept with the edits, never deleted. Whether macOS lets that alert run (logout may time out) is checked on the device.
8. **`signal ui` keeps its security rule** (`docs/ui-protocol.md` "Security notes"). Its Setup field reopens only the project it serves, from its files (a `.signal` file unpacked again), and refuses every other path.
9. **The Finder** associates `.signal` with Signal.app: the bundle's `Info.plist` exports the type `hu.d250.signal.project` (extension `signal`) and declares it a document the app edits. tao's `Event::Opened` opens a double-clicked file.

## Consequences
- A project can be handed over, mailed or kept as one file, and opened by a double click. The folder form stays fully supported, and nothing about how a project is read, planned or rendered changes: a `.signal` file renders bit for bit as its folder.
- The engine, the core and the graph are unchanged, and no crate is added. `zip` was already locked, and the `objc2-app-kit` features for the save panel and the alert add no package to `Cargo.lock`.
- Files an archive made elsewhere carries beyond the project files are unpacked, and are dropped when it is saved again.
- An app that crashes, or is quit from the Dock or by logout without an answer, leaves its working folder under `Signal/Open/`. That folder is not cleaned up automatically; its edits can be recovered from there by hand.
- Tests: `crates/signal-project/tests/archive.rs` (round trip, determinism, exclusions, every refusal), `crates/signal-cli/tests/project_files.rs` (pack, unpack, render identity, play, `ui check`), `crates/signal-ui/tests/app_mode.rs` (open, edited, Save, Save As, close, `signal ui`'s reopen), `crates/signal-app/src/window.rs` and `crates/signal-app/tests/server.rs` (the menu, the prompt on each route, the window's requests), `crates/signal-app/tests/bundle.rs` (the plist), `ui/app/lib/document.test.js`.
