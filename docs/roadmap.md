## Owner decisions

- **2026-10-11, after M1:** "Start with realtime audio, live edits, a basic UI, and core primitives." M2 and M2.5 run together, and the core primitive library moves forward from later milestones into M2. M2.5's basic UI includes a simple parameter panel (GUI b) on top of the setup dialog and metering. The GUI toolkit is egui (ADR 0018). The new dependencies (cpal, rtrb, eframe) are locked in the root `Cargo.toml`.
- **2026-10-12, after M2.5:** "We want signal to be able to use all CPU/GPU cores." Groundwork as M2.6 before M3; design in ADR 0019 (operator, delegated).
- **2026-10-13, after M2.6:** "Solidify multithread and multi-GPU groundwork. It is essential and critical to use all processing capacity available on the hardware." M2.7 before M3. Networking several Macs was raised as a possible feature; the operator's proposal is pending the owner's go-ahead.
- **2026-10-14, after M2.7:** "The next should be the foundations of a nice UI interface… HTML-based… SVG and pixel graphics… fader, knob, 2D input, scope, meter, button… physical modelling in both sound and visuals." M2.8, design in ADR 0023 (operator, delegated).
- **2026-10-16, during M2.8:** "Like Native Instruments Reaktor, I want a UI component editor and a signal-path schematic… signal processing needs transparency." Versioning starts at 0.1.0 (tag `v0.1.0`), the last number counting commits. M2.9, design in ADR 0026 (operator, delegated); visual patching moves forward from *Later*.
- **2026-10-17, during M2.9:** "Before we start [the building blocks], we should produce all the completely fundamental building elements… NI Reaktor's pattern… a built-in set in the application from which everything can be built"; then "these core-cell-like things can be in Rust… a Rust source text", and "ok, let it be so". M2.10, design in ADR 0027 (operator, delegated); the FFT analyser moves forward from M4.
- **2026-10-17, during M2.10:** "When you are ready, make a working basic high-level project: a sophisticated piano-roll-like view driving a Moog emulator, a tape delay, a drum-machine-like sequencer, and a 909 kick made by synthesis, not a sampler, with a beautiful interface that resembles the originals." M2.11, design in ADR 0028 (operator, delegated).
- **2026-10-18, during M2.10:** asked whether Signal has an interface for live interaction with LLM models; chose MCP over a separate API ("ok, let there be an MCP that can edit, adjust, practically everything a human could"). M2.12, design in ADR 0029 (operator, delegated).
- **2026-10-19, during M2.10:** "the outer shell is a wire diagram dead end… I would suggest a scaling view of the wires, and a fully working path tracing"; then "I like this zooming-in, just let there be a down-scaling wiring… I leave it to you". M2.13, design in ADR 0030 (operator, delegated).
- **2026-10-20, after M2.13:** "Let us reach a state that can be released on GitHub, that is the next goal, a GitHub release." Licence GPL-3.0-or-later, public repository with its history unchanged, v0.2.0 pre-release, ad-hoc signing (no Developer ID), the development record kept with a note. M2.14, ADR 0031.
- **2026-10-21, during M2.14:** "Put it on our to-do list: https://github.com/idlefoundry/ca-72 — analyse its source and implement or import it, bring it into the Signal project." Backlog row CA-72; scheduled after the v0.2.0 release.
